# M0 Engine Rules

| File | Content |
|---|---|
| `cycle_inputs.md` | Cycle inputs with tags, Girão v4 inputs, component efficiency definition (isentropic, total-to-total), validation point, rated case (ADR-009), uncertainty band |
| `review_criteria.md` | HARD rules, health checks, info items, validation criteria |
| `station_ownership.md` | Station ownership (upstream module owns its exit), module scopes, budget and integration workflow |
| `icd.yaml` | Interface control document and module budgets; generated by `analysis/icd.py` from the active revision, do not edit |
| `martins_2015.yaml` | Martins 2015 (CFM56-3) EGT rise per efficiency point, plausibility reference [KS] |
| `girao_2023.yaml` | Girão 2023 validation case, info references, spool speeds (M8 info) |
| `tcds_e004.yaml` | EASA TCDS E.004 ratings and EGT limits [K] |
| `icao_edb_cfm56_7b27.yaml` | ICAO EDB v32 rows (generated by `tools/extract_edb.py`) [K] |

Workflow for module agents:
1. Read your budget in `icd.yaml` (`modules.<Mx>.budget`).
2. Check achieved values with `core.budgets.check_budget`.
3. M0 runs `engine.M0_engine.analysis.integration.integration_check` (default mode `thrust_held`); out of tolerance it drafts a CR to M0 with options (a) M0 params change, (b) module redesign. Nothing is applied automatically.
4. An approved params CR is applied by `core.requests.apply`: params written, cycle re-run (`analysis/calc.py`), new revision, `results.yaml` and `icd.yaml` regenerated.

Acceptance: `analysis/acceptance_M0.md`, tests in `tests/acceptance/test_M0.py`.
